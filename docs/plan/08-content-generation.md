# 08 · Content generation

Rule: **code controls difficulty, the LLM writes content, code checks it.**

## Who does what

| Step | Done by | Example |
|---|---|---|
| Pick difficulty | Scorer (`07`) | b = 0.4 for Souk Rush |
| Turn difficulty into knobs | Game `level_map` | 3 customers, 4 items each, 20% change rate |
| Write content | LLM, strict JSON | Customer names, items, short lines ("Two kilos of oranges, and some harissa") |
| Check content | Validators | Count, duplicates, word list, solver, novelty |
| Serve | Game plugin | Runs the jsPsych timeline |

Games that need no language (n-back sequences, reaction time, Corsi) are generated by code from a seed. No LLM, no delay.

**As built (WP2.2).** For every content game, code builds the whole structure from the seed and knobs (orders, word lists, matrices, worked solutions with the planted error), with plain template text, and that version always passes the validators. The LLM is only asked to make the words nicer: Souk Rush customer lines, Market List words for a theme we have no list for (UW4), Pattern Gap hint ladders, Spot the AI's Mistake step wording. Its answer is merged into the structure and validated; on failure it is repaired up to twice, then a pool item is used, then the code-built version. Served items are recorded in `agent.content_pool`, `agent.content_served` and the user's Qdrant `exercises` points (novelty). Code: `backend/generation/` (`generators/`, `pipeline.py`, `pool.py`, `prompts/`); vocabulary in `registry/content/themes.yaml`.


## Schemas

Every generator has a Pydantic schema, and the LLM is called with structured output against it.

```python
class SoukOrder(BaseModel):
    customer: str = Field(max_length=20)
    line: str = Field(max_length=120)
    items: list[str] = Field(min_length=1, max_length=6)

class SoukRushContent(BaseModel):
    theme: Literal["fruit", "spices", "bakery", "pottery", "mixed"]
    orders: list[SoukOrder]
    changes: list[OrderChange] = []
```

## Validators

Run in order; any failure triggers a repair or fallback.

1. **Schema:** parses, right counts for the requested knobs.
2. **Content rules:** no duplicates within a round; words from an allowed vocabulary when the game needs common words; length limits.
3. **Language filter:** no clinical words, nothing unsafe (`09`).
4. **Solver:** for puzzles (matrices, logic, Tower, mazes, Spot the AI's Mistake), a program checks there is exactly one correct answer and, for Spot the AI's Mistake, that the planted error is really an error.
5. **Novelty:** embed the content and search the user's `exercises` collection in Qdrant; reject if cosine > 0.9 to something served in the last 30 days.

## Repair loop

```
generate → validate ─ ok → serve
               └─ fail → repair (send errors back to the LLM) → validate
                                    └─ fail twice → take from pool
```

## Pools

- A background job keeps the `agent.content_pool` table filled (target: 30 items per game and level for P1 games); `agent.content_served` stops a user from getting the same item twice.
- Pool items went through the same validators.
- Play never waits on an LLM call.

## Pattern Gap (matrices) generation

LLMs are bad at making valid visual puzzles, so we don't ask them to. A program generates matrices from rules (rotation, count, colour progression, XOR of shapes), with the number of rules setting difficulty. The LLM only writes the hint ladder text. The solver confirms one correct option among the distractors.

## Spot the AI's Mistake generation

1. The program generates a puzzle and its correct solution steps.
2. With probability 0.7 the LLM is asked to introduce **one** subtle error in a chosen step type (arithmetic slip, wrong rule, skipped case); otherwise the solution stays correct.
3. The solver re-runs the steps and confirms the error (or the absence of one).
4. The user must flag the error or confirm the solution is right. Both are scored (`11`).

The consent screen discloses that Najma will sometimes show deliberately wrong reasoning in this game.

## Custom games from blocks (user asks for a new game)

The user says, for example: "Give me a game where I remember a phone number while doing maths."

1. The LLM writes a **recipe** using only known blocks. It never writes code.
2. Code validates the recipe (known blocks, sane timings, max 3 minutes, scorable).
3. The block engine runs it as a jsPsych timeline.
4. Scores count with `reliability` 0.3–0.5 (`07`), and Najma says so: "Fun game. I'm only counting it a little until it's been tested more."

### Blocks

| Block | Does |
|---|---|
| `show_items(items, ms_each)` | Flash items |
| `distractor(task, seconds)` | A filler task (maths, tapping) |
| `recall(kind)` | Free recall, ordered recall, or recognition |
| `choice(question, options, answer)` | Multiple choice |
| `timer(seconds)` | Countdown |
| `rule(rule_text, switch_after)` | A rule that may change |
| `react(target, distractors, deadline)` | Speed response |
| `feedback(level)` | Show result |

### Recipe example

```json
{
  "title": "Number and Numbers",
  "dims": {"working_memory": 1.0},
  "steps": [
    {"block": "show_items", "items": "digits:7", "ms_each": 800},
    {"block": "distractor", "task": "arithmetic:easy", "seconds": 15},
    {"block": "recall", "kind": "ordered"}
  ],
  "repeat": 3
}
```
